# AI CAR CLIP SORTER PRO ULTIMATE

تطبيق macOS (Intel) لتفكيك الفيديو إلى مشاهد، وتصديرها، وفرزها (متحركة / متوقفة / مستبعدة)، ورفعها اختيارياً إلى YouTube.
كل المعالجة محلية. بدون Docker أو Gradio أو متصفح أو خدمات مدفوعة.

## كيف تحصل على ملف DMG (بدون Terminal وبدون بناء على جهازك)

1. أنشئ مستودعاً جديداً على GitHub، ويفضّل **Public** (بناء Intel على مستودع Private يُحسب بدقائق مضاعفة).
2. ارفع **كل محتويات هذا المجلد** إلى المستودع، مع التأكد أن المجلد `.github/workflows/` مرفوع (هو مجلد مخفي).
3. افتح تبويب **Actions**، ثم اختر **Build macOS Intel DMG**، ثم اضغط **Run workflow** مرة واحدة.
4. انتظر انتهاء البناء (عادة 10–25 دقيقة).
5. في أسفل صفحة التشغيل، قسم **Artifacts**، حمّل `AI-CAR-CLIP-SORTER-PRO-MAC-INTEL`. بعد فك الضغط ستجد `AI-CAR-CLIP-SORTER-PRO-MAC-INTEL.dmg`.

يقوم الـ Workflow بكل شيء في تشغيل واحد: تثبيت Python والمكتبات وFFmpeg، تشغيل الاختبارات، بناء `.app`، فحص توافق Big Sur،
توقيع Ad-hoc، **تشغيل فحص ذاتي للتطبيق المبني نفسه**، إنشاء DMG، التحقق منه، ورفعه.

### إذا فشل البناء
افتح الخطوة الحمراء وانسخ رسالة الخطأ. أكثر خطوة قد تفشل في أول مرة هي **فحص توافق Big Sur** (إذا احتاج ملف ما macOS أحدث من 11.7)؛
يمكنك عندها إعادة التشغيل مع إلغاء خيار `strict_macos_check` للحصول على DMG مع تحذير، لكن لا يُضمن عندها عمله على Big Sur.

## أول تشغيل على الماك (التوقيع)

التطبيق **موقّع Ad-hoc فقط، وليس موثّقاً (Notarized) من Apple**، لأن ذلك يتطلب حساب Apple Developer مدفوعاً (99$ سنوياً)
وشهادة Developer ID. لذلك سيعرض macOS تحذيراً. الحل: اسحب التطبيق إلى Applications، ثم **انقر بزر الفأرة الأيمن ← Open ← Open**
(مرة واحدة فقط). إذا ظهر أنه «تالف»، نزّل الملف عبر المتصفح مجدداً، أو نفّذ مرة واحدة: `xattr -cr "/Applications/AI CAR CLIP SORTER PRO.app"`.

### الاستيراد التلقائي من مجلد (طابور الفيديوهات)
في صفحة **سير العمل** اختر **مجلد الاستيراد التلقائي** ثم اضغط **بدء**. يستورد التطبيق فيديو واحداً فقط بالترتيب الطبيعي (1، 2، 10)،
ثم يحلله ويفككه ويصدّره (ويفرزه ويرفعه إن فعّلت ذلك)، وبعد اكتماله يستورد الفيديو التالي تلقائياً، وهكذا حتى ينتهي المجلد.
إذا أوقفت العملية أو أُغلق التطبيق فالفيديوهات المكتملة تُتخطى عند الاستكمال، والملفات الجديدة المضافة للمجلد تُلتقط في التشغيل التالي.

### سلوك السلامة
- لا يُحذف أي ملف للمستخدم: الاستبدال والتراجع ينقلان النسخ القديمة إلى `.trash` داخل المشروع، والفرز لا يكتب فوق ملف موجود.
- التصدير يكتب إلى ملف `.part` ثم يعيد تسميته بعد النجاح، فلا تبقى ملفات ناقصة. وعند امتلاء القرص يتوقف بوضوح ويحفظ التقدم.
- الفيديوهات التالفة تُتخطى مع رسالة، ولا توقف باقي الدفعة.
- المشروع يُحفظ ذرياً مع نسخة `.bak` واستعادة تلقائية إن تلف الملف، وحفظ تلقائي كل 30 ثانية.
- شريط التقدم يعرض نسباً حقيقية فقط. عند غياب نسبة دقيقة يتحول إلى شريط متحرك.

### حدود يجب معرفتها
- **مساعد الفرز يقيس الحركة (Optical Flow) ولا يتعرّف على السيارات.** يعطي اقتراحاً بنسبة ثقة، والمقاطع غير المؤكدة تُترك لقرارك دائماً.
  عتباته قابلة للضبط من الإعدادات؛ جرّبه على مقاطعك قبل الاعتماد عليه.
- **YouTube:** عليك إنشاء عميل OAuth من نوع Desktop مجاناً في Google Cloud Console وتفعيل YouTube Data API v3، ثم استيراد ملف JSON من صفحة الرفع.
  قد يفرض YouTube خصوصية Private على فيديوهات المشاريع غير المدققة. لا توجد مسودات عبر الـ API، فـ Private هو الأقرب. للحصة اليومية حدود.
  اختيار القناة يتم أثناء الموافقة في Google (الحساب المرتبط هو القناة التي تختارها هناك).
  لا يُعدّ الرفع ناجحاً إلا بعد أن تعيد YouTube معرّف الفيديو ويتأكد وجوده.
- لا يُرفع شيء إلا إذا فعّلت **الرفع التلقائي** ووافقت في نافذة التأكيد؛ والرموز تُحفظ في **macOS Keychain** فقط.
- التوقيع Ad-hoc فقط، ليس Notarization (انظر أعلاه).

## الاختبار: ما الذي تم فعلاً وما الذي لم يتم

**تم اختباره آلياً (44 اختباراً، على Linux بـ FFmpeg وPySceneDetect وOpenCV حقيقية):** التقسيم والدمج والتجميع، اكتشاف المشاهد على فيديو حقيقي،
التصدير والتقدم والإلغاء وامتلاء القرص وسياسات الملفات الموجودة، الفرز والتراجع، حفظ المشاريع والاستعادة، منطق الرفع والموافقة (بمنصة وهمية)،
سير العمل كاملاً مع الإيقاف والاستكمال، والترجمة، وبناء الواجهة كاملة بالعربية والإنجليزية.

**لم يُختبر هنا (لا أدّعي نجاحه):**
- بناء `.app` و`.dmg` فعلياً وتشغيل التطبيق على macOS Big Sur. أول دليل حقيقي هو تشغيل GitHub Actions (يتضمن فحصاً ذاتياً للتطبيق المبني).
- مشغّل الفيديو (Qt Multimedia) والواجهة المرئية على شاشة حقيقية، فقد اختُبر بناؤها في وضع بلا شاشة فقط.
- رفع حقيقي إلى YouTube (يحتاج حسابك وبيانات OAuth). مسار الرفع مكتوب وفق توثيق Google لكنه لم يُجرَّب مع الخدمة الحقيقية.
- إصدار PySide6 6.5.3 المثبّت للتوافق مع Big Sur لم أستطع تشغيله هنا (يتطلب Python ≤ 3.11)؛ اختُبر الكود مع إصدار أحدث.
